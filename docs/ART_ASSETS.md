## 前置约定

- 美术资产由 AI 生图 / 生视频工具产出。
- **不含音频**（本阶段先跳过）。
- 不含粒子系统、Shader、Spine 骨骼绑定 —— 这些在 Unity 里实现，不属于"美术资产"范畴。
- **画面比例：9:16 竖屏（1080×1920）**。
- **阶段四招募演出方案**：先生成"招募姿"静态立绘 → 用立绘作为输入，AI 工具生成 3~4 秒视频 → Unity 用 VideoPlayer 播放。

## 一、角色资产

每个英雄需要：站立基础姿 + 招募成功姿 + 招募视频，外加可选的 Talk 半身像。

### 1.1 英雄 A / B / C — 站立基础姿（用于阶段一、二、三）

| 项目 | 规格 |
| --- | --- |
| 文件名 | `hero_A_idle.png` / `hero_B_idle.png` / `hero_C_idle.png` |
| 尺寸 | 1024 × 1536（人物占画面高度 ≥ 90%） |
| 背景 | **透明 PNG**（无背景） |
| 构图 | 正面或微侧站立全身像，居中，脚底贴下边缘，头顶留 5% 余量 |
| 视线 | 直视镜头（玩家） |
| 一致性 | 三个角色**镜头距离、构图比例、光照方向**保持一致；**仅角色本身有差异**（发型 / 发色 / 肤色 / 体型 / 服装细节） |

### 1.2 英雄 A / B / C — 招募成功姿（立绘 + 视频源图，二合一）

| 项目 | 规格 |
| --- | --- |
| 文件名 | `hero_A_pose.png` / `hero_B_pose.png` / `hero_C_pose.png` |
| 尺寸 | 1024 × 1536（与 idle 立绘一致） |
| 背景 | **透明 PNG**（用于静帧）+ **另存一张带场景背景的版本**作为视频生成的参考输入 |
| 构图 | 自信亮相姿态（叉腰 / 摆手 / 抬头微笑等），全身可见，居中 |
| 用途 | 1) 视频起始帧 / 视频生成的 reference image；2) 视频缓冲 / 兜底静帧 |

### 1.3 英雄 A / B / C — 招募成功视频（由 1.2 立绘生成）

| 项目 | 规格 |
| --- | --- |
| 文件名 | `hero_A_recruit.mp4` / `hero_B_recruit.mp4` / `hero_C_recruit.mp4` |
| 时长 | **3~4 秒**（严格） |
| 分辨率 | 1080 × 1920（竖屏） |
| 帧率 | 24 ~ 30 fps |
| 编码 | H.264 / MP4，Unity VideoPlayer 通用兼容 |
| 内容 | 输入 1.2 招募姿立绘，生成"角色亮相 + 自然小幅运动（呼吸 / 摆头 / 抛媚眼 / 摆造型）"的短片 |
| 数量 | **3 个视频**（每个英雄各一个） |
| 包体约束 | **3 个视频总大小 ≤ 3 MB**（每个 ≤ 1 MB）。如超出则考虑：(a) 复用 1 个通用视频；(b) 改 WebM；(c) 退回单张立绘 + DOTween 伪动画 |

### 1.4 英雄 A / B / C — 表情 / 半身（可选，用于 Talk 路径）

| 项目 | 规格 |
| --- | --- |
| 文件名 | `hero_A_talk.png` / `hero_B_talk.png` / `hero_C_talk.png` |

## 关键风险

- **视频包体**：Playable 上限通常 5 MB（FB / Google Ads）。3 个视频 + 全部图片 + Unity WebGL 输出可能超标。需在生成视频阶段就严格控制每个 ≤ 1 MB，必要时降至 1 个共用视频或退回静帧 + DOTween 方案。
- **AI 生图一致性**：3 个英雄、3 个招募姿、3 个 Talk 像必须风格一致（光照、画风、构图比例）。Prompt 阶段需明确"统一风格关键词"模板。
